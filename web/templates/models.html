{# Facts from the GGUF header, not the filename (§4.9 Phase N). One row per loadable model: shards are collapsed and `size` is the whole set, because a shard is a fraction and the old listing said otherwise. The last column is the one the old page could not answer — can it run *here* — and it reads off the GPU aperture, not free RAM (§6.12.0). #}

one leaf per model · size is all shards summed · “fits” is against the {{ pool_h }} GPU aperture at the model’s trained context · this page writes nothing: no ctx-size is set here, so a model runs at the context its own header declares

rows come from two places: {{ diskroot }} (yours — the portal manages it) and the Hugging Face hub cache, whose rows are labelled “hub cache” below. Both are loadable and both take per-model settings; the router discovers the cache on its own, so leaving it unlisted would hide models it can already serve. Its ids are read the way llama.cpp reads them — a settings section has to be called what the router calls the model.

{# The tree (owner Oct-18). Levels are the id's own metadata: the repository namespace is the quantizer (`general.quantized_by`), the stem is the model (`general.name`), the `:QUANT` tag is the file type (`general.file_type`); that triple is the index's unique key. The third level is a BRANCH per quant (owner Oct-18: "each quant of a model its own branch so a model card never shares space with another model") -- opening the branch IS selecting the model, and the card lives inside its own branch, never in a shared area. At most one branch is open at a time (the cards are dense by design). #}

groups rest closed; typing opens what it matches. Opening a quant branch shows that model's full card; opening another closes it. Sizes on a summary are that group's total on disk.
