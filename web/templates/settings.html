Settings

Launch settings for the portal-managed services. Values are persisted to ~/ai/config/ and take effect when the affected service is restarted — nothing restarts itself automatically.

Shared runtime environment all services

Variables in ~/ai/config/ai-env.env are read by every portal-managed service (llama.cpp router, ComfyUI, AI Portal) at start. Use this to point all services at a specific driver/library set — e.g. a particular ROCm core version — even when the system default differs.

Network access

reading interfaces…

Bind decides who can connect. loopback (127.0.0.1) is this machine only; lan binds one interface address; all (0.0.0.0) answers on every interface — the "other systems on our network can reach it" setting. Ports are validated live (numeric range, not assigned to another managed service, not already bound here). The right-hand column probes the LAN address, which is what proves a daemon is not loopback-only.

servicecurrentbindport changelive reachability
Nothing here is firewall-managed: the portal has no root, so if ufw is enabled it prints the ufw allow command you would run instead.
{# ------------------------ llama.cpp router authentication ---------------- #}

llama.cpp router authentication …

An open router is an unauthenticated inference endpoint (plus its Web UI) for everything on the network. llama.cpp supports --api-key-file, so the portal can require Authorization: Bearer <key>. Applying it means restarting the router — which drops any agent session riding on it.
