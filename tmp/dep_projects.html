Projects

Projects live in the projects root — the folder the portal is allowed to create projects in. Change it on Settings. Forgetting a project here removes it from the registry and never deletes the folder on disk.

New project

Lowercase letters, digits and single hyphens, 2 to 64 characters, starting and ending with a letter or digit. my-app is fine; My-App, -app, app--1 and app/x are not.

Tick the boxes a new project starts with. The shortlist is fixed: the portal's own best practices, not a place to type commands. A box whose toolchain is not on this machine is refused by name, with the install statement, and the boxes that can run still run.

.gitignore is not a box: it is written with the boxes you picked. The base ignores are always there, and each stack you tick — Python, Node, C++ — adds its own section. A project that ticks nothing still gets the base, because a folder that gets a repository later is the folder this file exists for. A .gitignore the project already has is left exactly as it is.

Opening text and a git remote

Your words go in the files as written; empty means the portal's own template. A remote is added as origin. Pull from the remote first fetches that repository's own default branch before the init files are written, so its README is kept and the templates fill only the gaps.

Registry

No projects yet. Create one, adopt a folder that is already in the projects root, or clone a project into the root and it will show up below.

Folders the registry does not know

A folder created by hand, with git clone, or by an agent, is a project the portal has not been told about. Adopting writes the registry only — it changes nothing on disk.
